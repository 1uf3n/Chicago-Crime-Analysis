# Run with Docker

Prerequisite: Docker Engine or Docker Desktop running, with Docker Compose v2. Run commands at the repository root. No pip dependencies are required. The same Python pipeline runs inside the image.

## Build and test

```bash
docker compose build
docker compose run --rm pipeline python -m unittest discover -s tests -v
```

## Extract, load SQLite, analyze and visualize

```bash
docker compose run --rm pipeline
```

Compose bind-mounts local `data/` and `reports/` into the container, creating those directories if needed. This preserves the SQLite database, frozen API pages and charts after the container exits. Open `reports/dashboard.html` on the host. The initial API download needs internet and can take several minutes. On Linux, a root-run container may create root-owned output files; use `docker compose run --rm --user "$(id -u):$(id -g)" pipeline` after creating writable `data` and `reports` directories if needed.

An application token is optional. Set `SOCRATA_APP_TOKEN` in your shell before running Compose. Do not put a token into source code or commit it.

## Replay the separately supplied snapshot offline

Extract `chicago-crime-snapshot.zip` into the repository root first, then run:

```bash
docker compose run --rm pipeline python src/pipeline.py --snapshot data/raw/snapshot-2026-11-10
```

No API request is made in replay mode. Build the image beforehand if working without internet.

## Equivalent Docker CLI commands (macOS/Linux)

```bash
mkdir -p data reports
docker build -t chicago-crime:local .
docker run --rm -v "$(pwd)/data:/project/data" -v "$(pwd)/reports:/project/reports" chicago-crime:local
```

## Architecture

The image contains `src/`, `config/`, `sql/` and `tests/`. SQLite uses a local file rather than a separate database service. Python starts the dependency-aware ETL DAG. The Compose volumes persist its outputs. GitHub Actions tests Python on three versions, validates Compose, builds the image and runs the tests inside Docker. CI does not download the full dataset.

The `python:3.11-slim` tag fixes a Python minor series, not immutable image bytes. For long-term reproducibility preserve the raw snapshot, the Git commit and a built image digest/archive. The PowerPoint remains a frozen presentation and is not regenerated by Docker.
